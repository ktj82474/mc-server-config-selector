和朋友联机开荒最烦的从来不是游戏本身。房主一关电脑，服务器就没了；存档只在房主那台机器上，谁想上线都得先问一句"你在不在"；想自己搭又卡在端口映射、Java 环境、启动脚本这几道坎上。

把这些事丢给一台云服务器，问题基本就解决了：机器 24 小时在线，存档在硬盘里而不是在某个人的桌面上，异地好友直接连地址就能进。真正需要你花心思的只有一件事——买多大的配置。

下面按这个顺序讲：Minecraft 服务端到底吃什么资源、不同玩法该配多少、`雨云` 游戏云目前有哪些档位和价格、怎么把成本压下来，以及从下单到朋友进服实际上要做的几步。

## 先搞清楚：MC 服务端吃的是什么资源

Minecraft 服务器是个很"偏科"的程序，三条资源线里，两条是硬门槛。

**单核主频决定 TPS 稳不稳。** 它极度依赖单核性能，单纯堆核数对 TPS 的提升有限。版本越新越吃单核，官方给游戏云写的参考口径是：1.18+ 版本的资源消耗约为 1.16+ 的两倍、1.12.2 的三倍。所以 1.20 往后的服，机型选择比核心数选择更重要。

**内存决定你能带几个人。** 这是最容易算错的地方。服务端启动后基础占用大约 1–1.5GB，每个在线玩家再额外吃 200–400MB，每多加载一个模组大约 50–200MB。原版 5 个人 2G 内存能跑，装到 50 个模组可能 10G 都不够。流行整合包开起来后尤其明显——200+ mod 的包和纯净服的资源需求根本不在一个量级。

**带宽决定掉不掉线。** 多人同屏、跑图、大量实体运算时对上行带宽的占用会明显上升，带宽不够的表现不是断连，而是操作延迟和 TPS 抖动。

> 一句话总结：内存算人数，单核算流畅度，带宽算网络体验。三者按玩法权重不同，但都不能缺。

## 雨云游戏云：两条路线，一套面板

`雨云` 的游戏云产品线分两条路，选择逻辑很明确。

**面板服（MCSM）** 走的是"省事"路线。底层是开源的 MCSManager 面板，网页上点几下就能开实例，支持 Minecraft Java 版和基岩版、泰拉瑞亚、饥荒一键部署，Minecraft 里几乎集齐了市面上的主流核心类型。除了预置服务端，也可以选纯 Java / Linux 环境（Docker）自己上传整合包，文件管理支持在线解压和 SFTP，用 FileZilla 连接也行。适合没开服经验、只想赶紧和朋友玩起来的人。

**VPS** 走的是"自由"路线。支持装 MCDR、跑 Robot 框架、组群组服，但需要自己装环境、配脚本、管进程。适合有开服经验、要跑多端或做特殊架构的人。

机型方面，面板文档里列出的 CPU 覆盖 E5 2666v3、Platinum 8275cl、Gold 6146、Ryzen 5900X、Ryzen 7950X、Ryzen 9950X、Intel i9 14900K。按社区整理的实测口径，单核顺序大致是 i9-14900K 和 Ryzen 9950X 居首，7950X、5900X 次之，E5 2666v3 单核偏弱，更适合低版本小型生存服或挂机服。

计费模式是另一个需要留意的点。除了常规的固定计费，`雨云` 还提供动态计费：以 CPU 使用率 20% 为基准线，低于这条线不计费，超出的部分按天结算"CPU 电费"。每天固定开服超过两小时，选固定计费更划算；只是周末偶尔开一下，动态计费的闲置成本明显更低。

网络这块，游戏云全系配 NVMe 固态硬盘、30+20G 免费硬盘空间和 200M 下行带宽，走 BGP 线路。默认的 NAT 机型是共享公网 IP，可以开 15 个端口映射，需要独立 IP 时可以加购；NAT 模式本身带共享高防，横向抗攻击能力对付常见的流量攻击够用。

2. 进入游戏云购买页，服务器类型选 MCSM 面板，机型按人数和模组量选，计费模式按每天游戏时长选。
3. 选好配置后提交订单，在"我的游戏云"里能看到刚创建的实例。
4. 点击"重装/切换游戏"，选服务端核心。原版或插件服选 Purpur、Paper 这类优化端；模组服选 Forge / Fabric，或者在纯环境里自己上传整合包的服务端压缩包。
5. 进入 MCSM 控制台，点"开启实例"，日志里刷出 `Done` 就是启动成功。
6. 如果是 NAT 机型，去"信息与监控"里的 NAT 端口映射管理，添加规则：内部端口填服务端实际监听的端口（Java 版默认 25565），协议选 TCP；基岩版是 UDP。有独立公网 IP 的机器跳过这步。
7. 复制映射出来的地址，在游戏里"多人游戏 → 添加服务器"填进去，能进就说明通了。
8. 服务器里没有管理员权限的话，在控制台输入 `op 你的游戏名` 给自己上 OP。

## 几个新手常踩的坑

**eula.txt 没改，服务器一开就关。** 首次启动会生成 eula.txt，把 false 改成 true 再启动，这是 Mojang 的用户协议，绕不过去。

**离线玩家进不来。** 服务端配置里的 `online-mode=true` 表示只允许正版账号。和朋友开私服的话改成 false；但开了离线模式，任何知道地址的人都能进，自己把握。

**端口映射填错方向。** 内部端口是服务端在机器里监听的端口，不是公网访问端口；这两个填反了，地址能复制、就是连不上。

**高版本模组服选了低单核机型。** 1.18+ 之后这条路基本走不通，宁可降 mod 数量或者加预算换 CPU，也别在老架构上硬开重型整合包。

**动态计费被当成万能省钱方案。** 它的逻辑是"闲置便宜、忙时加价"。如果服务器要 24 小时挂着给朋友随时进，固定计费反而更可控。
